---

## 一、Skill 的本质

Skill 是一个包含 `SKILL.md` 的目录，向 Agent 传授**专业领域的操作知识**——工具用法、工作流程、领域规则等。这是 AgentSkills（agentskills.io）兼容格式。

---

## 二、基础结构

```
skill-name/
├── SKILL.md          # 必须，唯一入口
├── scripts/          # 可选：可执行脚本（Python/Bash等）
├── references/       # 可选：参考文档（按需加载）
└── assets/          # 可选：输出资产（模板、图片等）
```

### SKILL.md 必须包含

```markdown
---
name: skill-name
description: 技能描述（触发机制，决定何时调用此技能）
---

# 主体（Markdown）
```

---

## 三、description 是核心

description 不只是说明文字，它是**唯一的触发机制**。应包含：
- 技能做什么
- **何时使用**（具体触发词、场景）
- 适合的场景 vs. 不适合的场景

```markdown
description: |
  飞书多维表格（Bitable）的创建、查询、编辑和管理。
  当用户提到"多维表格"、"bitable"、"数据表"、"记录"、"字段"时使用。
```

---

## 四、核心原则

### 1. 简洁优先（Concise is Key）

上下文窗口是公共资源。默认假设：**Agent 已经足够聪明**，只添加 Agent 确实不知道的内容。每一段话都要自问："这值得消耗的 token 吗？"

### 2. 渐进式披露（Progressive Disclosure）

三级加载机制：
1. **元数据**（name + description）— 始终在上下文（约100词）
2. **SKILL.md 主体** — 技能触发后加载（**< 500 行**）
3. **bundled resources** — 按需加载（脚本可直接执行，不占上下文）

SKILL.md 保持精简，详细内容放到 `references/`。

### 3. 设定适当的自由度

| 自由度 | 适用场景 |
|--------|---------|
| **高（文字指令）** | 多路径有效、依赖上下文判断 |
| **中（伪代码/脚本）** | 有既定模式、可配置 |
| **低（特定脚本）** | 脆弱易错、一致性关键 |

### 4. 不要重复造轮子

SKILL.md 和 references 文件**不要重复**信息。详细信息放 references，SKILL.md 只留核心流程和导航指引。

---

## 五、SKILL.md 写作规范

### Frontmatter

```yaml
---
name: feishu-bitable
description: 飞书多维表格的创建、查询、编辑和管理。
---

# 可选 metadata（如需系统级配置）
metadata:
  openclaw:
    requires:
      bins: ["python3"]
      env: ["FEISHU_APP_ID"]
    os: ["linux", "darwin"]
```

### Body 写作

- **使用祈使句**（"Use X to do Y"，而非 "You should use X"）
- 开门见山，先讲核心用法
- 进阶内容链接到 references 文件
- 长文件加目录（>100行时）

```markdown
# PDF 处理

## 快速上手

使用 pdfplumber 提取文本...

## 进阶功能

- 表单填写：详见 [FORMS.md](references/FORMS.md)
- API 参考：详见 [REFERENCE.md](references/REFERENCE.md)
```

## 六、目录组织建议

### 按领域拆分（多领域技能）

```
bigquery-skill/
├── SKILL.md
└── references/
    ├── finance.md
    ├── sales.md
    └── product.md
```

### 按变体拆分（多框架技能）

```
cloud-deploy/
├── SKILL.md
└── references/
    ├── aws.md
    ├── gcp.md
    └── azure.md
```

---

## 七、技能创建流程

1. **理解需求** — 具体使用例子
2. **规划内容** — scripts/references/assets
3. **初始化** — `scripts/init_skill.py <name> --path <path>`
4. **编辑实现** — 写 SKILL.md + 资源文件
5. **打包验证** — `scripts/package_skill.py <path>`
6. **迭代测试**

---

## 八、技能存放位置及优先级

| 位置 | 优先级 | 范围 |
|------|--------|------|
| `<workspace>/skills/` | 最高 | 单 Agent |
| `~/.openclaw/skills/` | 中 | 共享所有 Agent |
| 插件内 skills | 低 | 全局 |

同名冲突时，**workspace 优先**。

---

## 九、注意事项

- ❌ 不要创建 `README.md`、`CHANGELOG.md` 等辅助文档
- ❌ 不要在 description 中写"当用户问..."之类的废话
- ❌ 不要嵌套多层 references（保持一层深度）
- ✅ description 要具体，包含触发词和场景
- ✅ 脚本必须实际运行测试
- ✅ 遵循渐进式披露，SKILL.md 主体 < 500 行

如何把自己开发的skill发布到clawhub
assistant: [[reply_to_current]] 以下是将自建 Skill 发布到 ClawHub 的完整流程：

---

## 发布前准备

### 1. 安装 ClawHub CLI

```bash
npm i -g clawhub
# 或
pnpm add -g clawhub
```

### 2. 确认 Skill 目录结构

你的 skill 必须符合规范：

```
my-skill/
├── SKILL.md          # 必须（有正确的 name + description）
├── scripts/          # 可选
├── references/       # 可选
└── assets/          # 可选
```

### 3. 登录 ClawHub 账号

```bash
clawhub login
# 会打开浏览器引导登录
```

确认登录状态：

```bash
clawhub whoami
```

---

## 发布 Skill

### 方式一：直接发布单个 Skill

```bash
clawhub skill publish ./my-skill \
  --slug my-skill \
  --name "My Skill" \
  --version 1.0.0 \
  --changelog "首次发布"
```

### 方式二：批量同步（推荐）

```bash
clawhub sync --all
```

`sync` 会扫描当前目录下的所有 skill，自动检测新增/更新，交互式引导发布。

常用参数：
- `--dry-run` — 只预览，不实际上传
- `--all` — 不提示，直接发布所有
- `--bump patch|minor|major` — 自动版本号递增
- `--no-input` — 自动化/CI 使用

---

## 发布后验证

```bash
clawhub search "你的skill名称"
clawhub list   # 查看本地已发布的 skill
```

或在 [clawhub.ai](https://clawhub.ai) 网页搜索

---

## 注意事项

| 项目 | 说明 |
|------|------|
| **账号要求** | GitHub 账号需满一周方可发布 |
| **slug 唯一** | 每个 skill 的 slug 在站内唯一 |
| **版本管理** | 重复发布同版本会报错；更新用 `--bump` 递增 |
| **位置** | 推荐放在 `skills/` 目录下再发布 |

---
